# Restaurant Booking API

REST API для создания, просмотра и отмены бронирований в ресторане.

## Запуск

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
```

После запуска документация доступна по адресам:

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

Для запуска в Docker:

```bash
docker compose up --build
```

## Тесты

```bash
pytest
```

Тесты покрывают создание брони, валидацию входных данных, конфликт занятого слота,
получение списка, отмену и повторную отмену брони. Для endpoint-тестов используется
`httpx.AsyncClient`, для сервисного слоя — прямые вызовы бизнес-логики. Тесты используют
отдельную SQLite-базу в памяти и не затрагивают локальный файл `restaurant.db`.

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| `POST` | `/bookings` | Создать бронь |
| `GET` | `/bookings` | Получить список с фильтром `date` и пагинацией `limit`/`offset` |
| `GET` | `/bookings/{booking_id}` | Получить бронь по идентификатору |
| `DELETE` | `/bookings/{booking_id}` | Отменить бронь |

Пример создания:

```json
{
  "name": "Анна Иванова",
  "phone": "+79991234567",
  "booking_date": "2026-09-12",
  "booking_time": "19:00",
  "guests": 2
}
```

Все поля в `POST /bookings` обязательны. У `GET /bookings` все query-параметры необязательны:

- `date` — дата в формате `YYYY-MM-DD`;
- `limit` — число элементов страницы, от 1 до 100, по умолчанию 20;
- `offset` — число пропускаемых записей, по умолчанию 0.

## Ошибки API

- `422 Unprocessable Entity` — данные запроса не прошли валидацию: неверный телефон,
  дата, время, число гостей или параметры пагинации;
- `404 Not Found` — бронь с указанным идентификатором не найдена;
- `409 Conflict` — слот уже занят либо бронь уже отменена.

## Принятые решения

Данные хранятся в SQLite через async SQLAlchemy 2.0; миграция для схемы базы добавлена в Alembic. Pydantic отвечает за формат входных данных и возвращает стандартный ответ FastAPI со статусом `422` при ошибках валидации. Сервисный слой содержит операции с базой и бизнес-правила: занятый активной бронью слот возвращает `409`, а отмена меняет статус на `cancelled`. Отменённый слот можно забронировать снова; повторная отмена одной и той же брони возвращает `409`.

## Что можно было бы добавить

При развитии сервиса стоило бы добавить аутентификацию сотрудников, управление столиками и вместимостью и защиту от конфликтов одновременных запросов на один слот на уровне базы данных.
